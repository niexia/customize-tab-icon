# Store kit

<!-- release: 1.1.0 -->

Everything needed to update the Chrome Web Store listing for Changicon. The copy
is in Markdown so it can be reviewed in a pull request; the dashboard itself
takes plain text, so paste the contents of the code blocks.

## Contents

| File | Purpose |
| --- | --- |
| [`listing.md`](listing.md) | Title, summary, description, category, language, URLs, asset map |
| [`permissions.md`](permissions.md) | Single purpose, per-permission justifications, data usage, remote code, certifications |
| [`privacy.md`](privacy.md) | Public privacy policy (link this from the dashboard) |
| [`review-notes.md`](review-notes.md) | Reviewer test instructions |
| [`checklist.md`](checklist.md) | End-to-end submission checklist |
| [`promo-video.md`](promo-video.md) | Optional 20–30 s promo video storyboard |
| [`assets/`](assets/) | Exact-size PNGs for the dashboard |

All screenshots are full-bleed truecolor PNG with no alpha channel. The Chrome
Web Store displays them downscaled to 640×400; keep text large and avoid fine
detail at the edges.

`store-icon-128.png` is copied from `public/icon/128.png`. The artwork should stay
within a 96×96 safe area with 16 px of padding if you redesign it; the packaged
extension icon and the store icon are the same file.

## Regenerating

```bash
pnpm build          # or just: pnpm store:assets (it builds first)
pnpm store:assets
```

Requirements:

- Node 22+.
- A local Google Chrome/Chromium. The script finds the macOS app path
  automatically; elsewhere set `CHROME_PATH=/path/to/chrome`.
- No network access is required; everything is served from `127.0.0.1`.

The script:

1. Copies `.output/chrome-mv3` to `.store-demo/`.
2. Injects `scripts/store/mock-chrome.js` (storage/tabs/runtime/scripting mock),
   `scripts/store/scenario.js` (opens a picker, types text, attaches a fake file),
   and a no-animation stylesheet.
3. Serves the directory locally and captures the **real popup bundle** with
   headless Chrome. Five 1280×800 marketing frames are composed around a browser
   mock; six 2× popup captures go to `docs/screenshots/`.
4. Verifies every PNG's dimensions and rejects alpha channels before writing.
5. Cleans up `.store-demo/` unless `--keep` is passed.

`STORE_DEBUG=1 pnpm store:assets` forwards Chrome's output when a capture fails.
The script uses `spawn`, not `spawnSync`, so the in-process server stays
responsive while Chrome loads the page.

### Why the screenshots show a mock

The popup talks to `chrome.tabs`, `chrome.storage`, `chrome.runtime`, and
`chrome.scripting`. Those APIs do not exist on a plain web page, so the harness
provides a minimal mock and seeds storage with an applied icon. The UI itself is
the production bundle; no component is reimplemented. The mock never ships in
the extension.

### Known caveat: the native file input

Chrome renders `<input type="file">` with the **host OS language**. On a Chinese
macOS, the upload popover shows “选择文件 未选择任何文件” even with
`--lang=en-US`. That is why the five English store screenshots use the text
badge instead of the upload flow. The upload feature is still described in the
listing and is covered by the app.

If you need an English upload screenshot, capture it on an English-locale OS (or
a CI browser image with an English locale). Do not retouch the screenshot to
replace the control; a real capture is less misleading. `docs/screenshots/popup-upload.png`
is generated for localized listings and internal review only.

## Using the kit for a submission

1. Follow [`../docs/release-process.md`](../docs/release-process.md) to build and
   tag the release.
2. Upload the zip in the Developer Dashboard.
3. Paste the fields from [`listing.md`](listing.md).
4. Upload the assets from `assets/`.
5. Fill the Privacy practices tab from [`permissions.md`](permissions.md).
6. Paste [`review-notes.md`](review-notes.md) if the field is offered.
7. Walk through [`checklist.md`](checklist.md) before hitting submit.

Use the dark/emoji/icons/text/light images in the README. They are 2× captures so
they stay sharp on high-density displays; set a CSS width of about 320 px when
embedding them.

## Keeping copy and assets in sync

- Change behavior → update [`../docs/architecture.md`](../docs/architecture.md).
- Change UI → run `pnpm store:assets` → review the five screenshots → update the
  README images.
- Change features or permissions → update `listing.md` and `permissions.md` in the
  same commit.
- Change the privacy policy → update the effective date and the dashboard URL if
  the hosting location changed.
- Run `pnpm docs:check`; it verifies all of the above except prose accuracy.
